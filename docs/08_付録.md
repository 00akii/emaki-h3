# 08. 付録

## 実測値の一覧

本マニュアルの数値の一覧です。**すべて開発環境（下記）での実測**で、環境により変わります。測定の詳細のうち公開されているものは [README](../README.md) と [設計書](../設計書.md) にあります。

### 実測環境

| | |
|---|---|
| GPU | NVIDIA RTX 4090 24GB |
| OS | Windows 11 Pro |
| ComfyUI | 0.33.1（`--reserve-vram` なし） |
| Python | 3.10 |
| LLM | LM Studio + `qwen3.6-27b-uncensored-heretic-v2-native-mtp-preserved@q4_k_s`（ctx 16384） |

**GPU の電力リミットも所要時間に効きます。** この機は MSI Afterburner で電力上限を管理しており、絞ると明確に遅くなります。プロンプト生成は、電力リミットが **50%（225W / 450W）** に絞られていた日に **22〜28秒**の実測がある一方、別の日には **15〜16秒**の実測もあります（このときの電力リミットは記録が無く不明）。以下の数値がどの電力設定で測られたかは区別していないので、**幅の上寄り・下寄りのどちらに当たっても異常ではありません**。

### 所要時間

| 項目 | 実測値 | 条件 |
|---|---|---|
| プロンプト生成 | 15〜30秒/回 | ComfyUI が VRAM を空けているとき（抱えたままだと35秒前後）。**この開きの主因は GPU の電力リミット**（下記）で、ブリーフの長さの影響は副次的 |
| プレビュー生成（608×352） | 126.2 / 127.9 / 132.8 / 141.6 / **336.0** 秒（5本の実測値。平均は取っていない） | 2026-08-25・電力リミット360W・参照素材なし・同一プロンプト。**生成のたびに毎回モデルを読み込み直す**（既定の挙動） |
| 本番生成（1344×768） | 約16分（15.6分の実測1本） | 2026-08-23。このときの GPU 電力リミットは記録が無い |
| 切り抜きの threshold スイープ | 約10〜17秒（6点） | |
| 切り抜きの検出 | 約1〜7秒 | |

### 効く・効かない（生成 61〜73本のブラインド判定＝何を指定したかを伏せて結果だけで判定する方式・による）

| 指定 | 結果 |
|---|---|
| カメラ（終端）の方向 | **12/12 で方向どおり**。終端未指定の対照 6本中 5本が静止 |
| 開始の構図: 高さ（目線／ハイ／ロー） | 効く |
| 開始の構図: 真俯瞰（真上から） | **効く**（2026-08-27 追加）。壁が写らない真上の画になる。**選択肢にあります** |
| 開始の構図: 虫の視点（極端なローアングル） | **未確認。選択肢にありません。** 旧検証では真俯瞰と同じ「1段手前で頭打ち」だったが、真俯瞰の失敗が本文の描写ミスマッチによるものと判明した今、同じ原因かは**再検証していない** |
| 開始の構図: 視点（正面／真横／背面） | 効く（斜め45度は 4件中2件で不安定） |
| 開始の構図: サイズ（寄り） | **プロンプトの描写を画角内に絞る修正とセットでのみ効く**（絞らないと ×9、絞ると ×0）。アプリが自動で修正 |
| 被写界深度（背景ボケ） | プロンプトの描写で物理的に書けば効く（アプリのチップが対応） |
| ダッチアングル（画面が斜めに傾く） | **効く**（2026-08-27 訂正・**選択肢にあります**）。以前「3/3 で水平のまま」としていたのは誤りで、**当時のプロンプトはカメラ指示だけを傾け、本文は水平な世界を描写していた**。本文ごと傾いた世界として描くと効く。**ただし傾く向きと角度は選べない**（実生成の機械測定で24.5度。ブリーフ→ローカルLLM→プロンプト→生成の全経路で確認済み） |
| 広角レンズの誇張された遠近 | **効く**（2026-08-27 訂正・**選択肢にあります**）。同じく本文ごと広角の世界として描くと効く。**誇張の強さは選べない**（魚眼に近くなることがある） |
| 望遠レンズの圧縮 | **効かない。**本文ごと書き換えた徹底検証でも 2/2 で通常の遠近になった（2026-08-27 再確認）。**唯一の本物の「効かない」** |
| 引きで始めて「足元から顔まで舐め上げる」 | 成立しない（0/2。静止か寄りに化ける） |
| ジャンル差（実写調 vs 2Dアニメ調） | 挙動差なし |

### 画面内の文字（12本の実測）

| 字種 | 結果 |
|---|---|
| ひらがな・カタカナ・常用漢字（JIS第1水準）・英数 | **9/9 で正確に描画** |
| JIS第2水準（例: 鵺鰰） | 偏だけ合って**旁が別の実在漢字**になる |
| 異体字（例: 髙﨑） | **通常字体（高崎）に黙って置換** |
| 国字 | 割れる（辻○ 峠×。複雑で稀な字ほど崩れる） |
| カメラが動く場合 | 崩れない（静止と同等） |
| 文字数 | 実測は5文字まで。6文字以上は未検証 |

### その他

| 項目 | 値 |
|---|---|
| 尺の上限 | 実務上 **10秒**。それ以上は破綻する。**参照素材が増えるほど安全な尺は短くなる**（Comfy-Org/ComfyUI#15738） |
| フレーム数 | 24fps。モデルの都合で刻まれるため実尺は指定と少しずれる（例: 8秒 → 192f = 8.00秒、5秒 → 124f = 5.17秒） |
| bit_rate の正常域 | 1344×768 で 11〜14 Mbps（解像度で按分。608×352 なら 2.3 Mbps 前後） |
| 音量の正常域 | mean -45 dB 前後（-70 dB 未満はほぼ無音） |
| 推奨 LLM の合格率 | 56/56（7ケース×8シード）。モデル一覧のラベルは別途17モデルの比較実測による |
| threshold と検出数の例 | 0.35→34人 / 0.5→23 / 0.7→9 / 0.9→1（1枚の群像絵での実測。絵ごとに変わる） |
| クロップの効果例 | 群像の端の人物の占有率 2% → 31.5% |
| 参照動画の使用範囲 | **2.0秒〜6.04秒だけ**（先頭2.0秒を捨て、そこから約4.04秒ぶんを読む）。サムネイルは先頭フレームだが使用範囲ではない |
| 参照動画の解像度縮小の効果 | 自動で608×352に縮小。縮小せず1280×720のまま使うと総所要+72.1%（711秒→1224秒の実測） |
| seed に指定できる範囲 | **0以上、2⁵³-1（約900兆）以下の整数。** 負の数は ComfyUI が受け付けない（`noise_seed` の仕様）。上限を超えるとブラウザ内で値が黙って化ける（実測: `12345678901234567890`→`12345678901234567000`） |

## できないこと・未検証の一覧

**「未検証」は「動かない」ではなく「実測していないので保証しない」の意味です。**

| 項目 | 状態 |
|---|---|
| おまかせ（モードA）の展開 | **未検証**。展開されるのは場所・動き・カメラ・セリフの4欄のみ |
| 解説 .md の生成 | API のみ・画面未接続・未検証 |
| 画面内の文字: 6文字以上・複数行・縦書き | 未検証 |
| `config.gen.vram_mode` の `auto` | **常に `share` と同じ動作**（2026-08-26 の変更。以前は特定条件で VRAM を解放しない設定を選び、詰まりを起こしていた） |
| `config.gen.vram_mode` の `resident` | **既知の問題があり非推奨。** VRAM を解放しないため、デコード段階で詰まりやすい（実測9本中4本が、時間がかかる・完了も中止もできずComfyUIの再起動が要る、のいずれかになった）。手動で `config.json` に設定しないかぎり選ばれない。**うまくいった回が速いのは「連続して投入したから」ではなく「この設定だから」**——既定の `share` では、投入間隔を詰めて連続生成しても126〜196秒かかる（実測） |
| ComfyUI 起動引数 `--reserve-vram 3` | **効果なしと実測済み（2026-08-25）。** 付けて起動していても、遅くなる回・完了も中止もできなくなる回の両方が発生する。以前は推奨として案内していたが撤回 |
| 切り抜きの点・枠指定 | 画面から使えない（テキスト検出のみ） |
| 望遠レンズの圧縮 | **効かないことが実測済み**（だから選択肢に無い）。**ダッチアングル・真俯瞰・広角は 2026-08-27 に「効く」と分かり、選択肢に追加しました** |
| 尺 10秒超 | 破綻する（実測） |
| 生成結果の自動判定 | しない設計（採否は人が決める） |
| 外部公開 | 不可（認証なし・127.0.0.1 前提） |
| 過去のジョブ一覧 | `jobs/` を全部読むため、件数が増えると遅くなる |

## 用語集

| 用語 | 意味 |
|---|---|
| 作品 | スタイル宣言・キャラ定義・参照素材・生成履歴をまとめる単位 |
| ショット | 作品の中の1カット（S01, S02, …）。「採用」で進む |
| ブリーフ | 日本語で書く指示（6欄）。ここから LLM がプロンプトを書く |
| プロンプト | MiniMax-H3 に渡す英語の構造化テキスト |
| 機械検査（リンター） | プロンプトの書式・整合性の自動チェック。ERROR / WARN と D番号で報告する |
| プレビュー / 本番 | 608×352（確認用）と 1344×768（納品用）の生成 |
| 採用 | 結果を作品の記録に確定させる操作 |
| 参照素材 | 生成に渡す画像（キャラの見た目）と動画（モーション参考） |
| キャラ表 | キャラの見た目を示す参照画像。切り抜き済みが望ましい |
| 切り抜き | 元イラストから人物だけを単色背景に抜くこと（SAM3） |
| 生画像 | 切り抜いていない背景つきの画像。プレビュー専用 |
| threshold | 切り抜きの検出のしきい値。高いほど検出が絞られる |
| コンタクトシート | 動画から等間隔に9フレームを並べた確認用画像 |
| seed | 乱数種。同じ seed・同じプロンプトなら ComfyUI はキャッシュを返す |
| t2va / ref2va | 参照素材なし／ありの生成モード。参照を選ぶと自動で ref2va になる |
| フレーム間差分 | 隣接フレームの平均絶対差。動き・ちらつきの目安 |
