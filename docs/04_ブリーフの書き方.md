# 04. ブリーフの書き方

ブリーフはあなたが日本語で書く指示です。ここからローカル LLM が MiniMax-H3 用の英語プロンプトを書きます。**動画の出来はほぼこの欄で決まります。** この章では欄ごとに「何を書くか・良い例・悪い例・なぜそうなるか」を説明します。

> 本章の「効く／効かない」は、開発環境での実測（生成 61〜73本を、何を指定したかを伏せて結果だけで判定する方式＝ブラインド判定ほか）に基づきます。出典は [08. 付録](08_付録.md)。

## モードの選び方（A・B・C）

| タブ | 何か | いつ使うか |
|---|---|---|
| **推奨（B）** | 6欄に分けて書く。**既定** | 通常はこれ。以下この章はモードB の説明です |
| おまかせ（A） | 1行書いて「欄に展開」を押すと、LLM が推奨モードの欄に展開する。展開結果を確認してから生成に進める | **展開機能は未検証です**（実測での動作確認をしていません）。展開されるのは**場所・動き・カメラ・セリフの4つ**だけで、開始の構図と画面内の文字は必要なら手で足します。結果を必ず確認し、おかしければ推奨モードで直してください |
| 詳細（C） | `MODE / DURATION / RATIO / STYLE / REFS / SHOT / FRAMING / CAMERA / TEXT / DIALOGUE / SOUND / MUSIC` の全キーを直接書く | ブリーフの組み立てを全部自分で制御したいとき。書式は [README](../README.md) と vendor/system_h3.txt を参照 |

## 場所と時間

**どこで・いつ・何でできているか**を書く必須欄です。

- 良い例: `夕立のあとの夕方、学校の屋上。濡れたコンクリート`
- 良い例: `夜の自室。木の机と紙のノート、硝子のコップ`
- 悪い例: `幻想的な雰囲気の場所` — 画に落ちません

**素材名（コンクリート・鉄・硝子・木など）を1つ入れると画が締まります。** 参照画像の背景が漏れてくるのを、新しい場所の「具体物」で押し返す仕組みだからです（実測）。雰囲気の形容だけでは押し返せません。

## 動き

**順番どおりに区切って書きます。** 3〜5段階が目安。最後に止まる状態まで書き切ってください。

- 良い例: `机に座っている 顔を上げる 立ち上がる 鞄を肩にかける`
- 悪い例: `自然に動く` `いい感じに` — 何も渡りません

**区切りは打ちやすいもので構いません。** スペース（半角・全角）・読点「、」・カンマ・ハイフン「 - 」・改行・矢印「→」のどれでも同じに扱われ、LLM には `A → B → C` の形に揃えて渡ります。どう区切られたかは**入力欄のすぐ下に段階として表示される**ので、割れ方がおかしければその場で書き直せます。`3-5歩` のような数値範囲は割られず、長音「ー」も区切りになりません。

**動きの質は参照動画ではなく、この欄の文章で決まります**（実測）。参照動画を渡していても、ここが曖昧なら曖昧な動きになります。

## 開始の構図

**1フレーム目がどんな画か**を指定する任意欄です。チップから選ぶか、自由に書きます。空欄なら LLM が選びます（たいてい全身の引き）。

チップは「サイズ／高さ／視点／質感・特殊」に分かれています。**実測で効いたものだけが並んでいます:**

- **高さ**（目線／ハイアングル／ローアングル）と**視点**（正面／真横／背中側）は、選ぶだけで確実に効きます
- **サイズ**（ドアップ〜引き）は事情が違います。下の「3つの判定」を読んでください
- 「斜め45度」は**不安定**です（実測 4件中2件しか当たらず、正面か真横に寄る）。チップに注記があります
- **ダッチアングル・真俯瞰・広角は選択肢にあります**（2026-08-27 追加）。以前は「効かない」として載せていませんでしたが、**当時の検証はカメラ指示だけを変えて本文は普通の世界を描写していた**ための誤りでした。選ぶと、場面全体をその効果に矛盾しない世界として描くよう自動で切り替わります。**ただし傾く向き・角度・誇張の強さは選べません**（傾きは実生成の機械測定で24.5度。ブリーフから生成までアプリの全経路で確認済み）
- **望遠の圧縮だけは選択肢にありません。**本文ごと書き換えても効かないことが確認できているためです（選んでも変わらないものは置かない方針）

### 3つの判定 — 欄の下に出るバッジの意味

開始の構図とカメラ（終端）の組み合わせは、入力するたびに機械判定され（LLM は使いません）、結果が欄のすぐ下に出ます。

| 判定 | 意味 | あなたがすること |
|---|---|---|
| **そのまま通す** | プロンプトの描写と衝突しない組み合わせ | 何もしなくてよい |
| **修正が入る** | 開始が「胸から上」より寄っていて、カメラが引かない。そのままだと**プロンプトの場所描写が勝って、寄りの指定が黙って無視される**（実測: 絞らないと ×9、絞ると ×0）。そこで自動的に、場所欄を「背景のヒント」に降格し、プロンプトの描写を画角内の要素（表情・髪・布地・手元・光）に絞る修正が入る | 修正は自動です。**場所欄に書いたものが画面に映らなくなる**ことだけ理解しておく。実際にどう渡ったかは右ペインの「ブリーフ（実際に LLM へ渡した文）」で見られます |
| **成立しにくい** | 逃げ場のない組み合わせ。(a) 寄りで始まってカメラが引く — 冒頭を寄りにするにはプロンプトの描写から部屋を消す必要があり、消すと終端に書くものが無くなる。(b) 引き（全身が画面内）で始まって「足元から顔まで舐め上げる」— 全身が既に見えているので動く意味がなく、静止か寄りに化ける（実測 0/2） | 警告のみで生成は止まりません。開始か終端のどちらかを変えるのが安全です |

**寄り・引きを確実にしたいときは、開始の構図ではなくカメラ（終端）で指定する方が通ります**（終端としてのサイズ指定はプロンプトの描写を絞らなくても 12/12 で届いた実測から）。

## カメラ（終端）

**カメラがどこで止まるか＝最後の画**を書く任意欄です。**空欄だと静止ショットになります。**

- 例: `顔が画面の上半分を占めるまで寄る` / `場所全体が見えるまで引く` / `横に流して画面の反対側の相手が入るまで`
- チップの10種は方向どおりに動くことが実測済みです（12/12）
- 到達する画角は目安で、保証ではありません
- 「動かさない（構図を保つ）」を選ぶと静止を明示できます

書き方のコツは「動き方」ではなく**「最後にどんな画になっているか」**を書くことです。振幅や速さのタグ（大きく・速くなど)より、終端の構図の記述が効きます。

## 画面内の文字

看板・札・画面などに出す文字を指定する任意欄です。

**書式**: `看板に「こんにちは」` — カギカッコの中が**一字一句そのまま**画面に出ます。前に「看板に」「ネオンで」など載せる物を書けます（省略すると LLM が画角内に看板か画面を置きます）。

入力するとすぐ下に判定が出ます:

| 表示 | 意味 | あなたがすること |
|---|---|---|
| **出ます** | ひらがな・カタカナ・常用漢字（JIS第1水準）・英数字。**実測 9/9 で正確に描画された範囲** | そのまま使えます |
| **別の字になる恐れ** | JIS第2水準の漢字や異体字（髙・﨑など）が含まれる。**読めない字に崩れるのではなく、もっともらしい別の実在漢字に静かに置き換わります**（実測: 鵺鰰 → 偏だけ合って旁が別字、髙﨑 → 高崎）。一見正常に見えるため見逃しやすい | 常用の字に言い換えるのが安全。使うなら**生成後に必ず自分の目で読んで確かめる** |
| **長さが未検証** | 6文字以上。実測したのは5文字（「こんにちは」）まで | 出ないという意味ではありません。出来を確認しながら使ってください |

補足:

- **カメラが動いても文字は崩れません**(実測)。「文字を出すなら静止」という制約は不要です
- 複数行・縦書きは未検証です
- 開始の構図で「修正が入る」判定になっても、この欄は画角外扱いになりません（場所欄と別に渡す設計のため。手に持つ看板の文字が実測 3/3 で残っています）
- 指定した文字がプロンプト本文に入らなかった場合は検査（D13）が検出し、自動修復が働きます。**機械検査に通らないと、画面にはこの D13 のように番号つきで ERROR/WARN が出ます**（他の項目も同じ形式です）

## セリフ

話者の説明とセリフを `キャラ（性別・年齢・声質）「セリフ」` の形で書きます。カギカッコの中は一字一句そのまま入ります。

- 例: `少女（落ち着いた低め）「またね」`
- **8秒の動画なら日本語30文字以内が目安**です。詰め込むと早口になります

## 尺・比率・seed

参照素材の下の3つです。

- **尺** — 4〜10秒。**上限が10秒なのは、それ以上で映像が破綻するため**です（実務上の実測。参照素材が多いほど安全な尺は短くなります。Comfy-Org/ComfyUI#15738）。画像3枚以上または動画2本以上を選んで9秒以上にすると、フレーム数表示が警告色になります
- 尺の右の `→192f · 8.00s` は実際のフレーム数と実尺です。モデルの都合でフレーム数が刻まれるため、**実尺は指定とわずかにずれることがあります**（例: 5秒 → 124f = 5.17秒）
- **比率** — 16:9 / 9:16 / 1:1 / 4:3 / 21:9
- **seed** — 乱数種。**0以上の整数**を書きます（0も使えます。空欄なら1）。**負の数は使えません**——ComfyUI の仕様上受け付けず、書くと生成前にエラーで止まります。**2⁵³-1（約900兆）を超える数も使えません**——ブラウザの中で値が黙って変わってしまうため、アプリ側で弾いています
- **欄の右の「ランダム」ボタン**を押すと、この範囲の具体的な数字が自動で入ります。ComfyUI に「-1で毎回変える」という指定は存在しないので、これが正しいランダム化の方法です。**使った値は結果カードとジョブ記録に残るので、良かった回をあとで再現できます**
- **同じ seed・同じプロンプトで再投入すると、ComfyUI はキャッシュを返すだけで再生成されません。** 少しだけ変えたいときは、結果カードの「seed+1 で再生成」が近道です（詳しくは [06. 生成と結果](06_生成と結果.md)）

## LLM のモデルを選ぶ

上部の「モデル」から。一覧には手元の実測（17モデルの比較）に基づく合格率ラベルが付き、**推奨モデルが上に出ます**。未検証のモデルは「未検証」と表示されます。ラベルは開発環境での実測なので、別のモデルを使うときは出来を見ながら判断してください。

**クラウド LLM（OpenAI 互換）に切り替えると料金がかかります。** 切り替え中は上部に「☁ クラウド使用中」が常時出て、生成のたびに確認ダイアログが開きます（1回あたり約 8〜9k トークン）。API キーは環境変数名で指定します — **キーの値を config.json に書かないでください**。24GB 未満の GPU で GPU 切り替えなしに使いたい場合の選択肢です。

## プロンプトを読む・直す

「プロンプトを生成」を押すと、LLM がプロンプトを書き、機械検査（リンター）が通らなければ**最大3回まで自動で直します**。所要は開発環境の実測で1回あたり15〜30秒ほど（ComfyUI が VRAM を抱えたままだと35秒前後に延びます）。**この幅は主に GPU の電力設定によるもの**です（同じ機材でも、電力リミットを 50%（225W / 450W）に絞っていた日は22〜28秒でした。別の日の15〜16秒の実測時に電力リミットが何%だったかは記録がなく不明ですが、主因は電力設定と見ています）。ブリーフの長さでも多少変わりますが、影響はそちらが主ではありません。

右ペインのプロンプトカードで:

- **バッジ** — `ERROR 0 / WARN 0` なら合格。ERROR が残っていれば内容を読んで判断します
- **プロンプトは直接編集できます。** 直したら「再検査」でリンターを通し直す
- **やり直す** — LLM にもう一度書かせます。**seed は効きません**——同じブリーフ・同じ seed でも、ローカル LLM は毎回違う文を返します（実測: 28本中28本が本文不一致）。何度か試して良いものを選ぶ、という使い方になります
- **プロンプト.txt に書き出す** — `config.prompt_txt` を上書きし、アーカイブにも保存して作品の履歴に残す

**ここが唯一の必須確認点です。** プロンプトを読んで、ブリーフの意図（場所・動きの順序・文字・セリフ）が英語のプロンプトに入っているかを見てから生成に進んでください。生成そのものは [06. 生成と結果](06_生成と結果.md) へ。
